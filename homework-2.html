Homework 02

Encryption and Cryptanalysis

Comparing an elliptic-curve encryption scheme with the Caesar cipher, then investigating their weaknesses.

Aim of the experiments

We encrypt and decrypt the same message using two schemes: the Caesar cipher and a hybrid scheme based on secp256k1, with an intentionally restricted recipient private-key space.

We then investigate two attacks: statistical recovery of the Caesar shift and exhaustive search of the restricted elliptic-curve private-key space.

1. The Caesar cipher

Each letter is replaced by the letter a fixed number of positions further along the alphabet. We encode A,…,Z as 0,…,25.

Encryption: c = (p + s) mod 26.
Decryption: p = (c − s) mod 26.

Here p represents a plaintext letter, c a ciphertext letter, and s the secret shift. Encryption and decryption use the same key, so this is a symmetric cipher.

ASCII letters are converted to uppercase. Spaces, digits and ASCII punctuation are preserved. Accented letters are not supported in this experiment. Both encryption schemes will use the same normalized text.

Key space and statistical properties

        
          

            There are 26 possible shifts, including zero, which leaves
            the message unchanged. The same plaintext and key always
            produce the same ciphertext.
          

        
          

            Every occurrence of a letter is replaced by the same letter.
            Letter frequencies are therefore shifted, not hidden.
            Repeated-letter patterns remain visible. In this implementation,
            spaces and punctuation also reveal part of the message structure.
          

        
          

            Correct decryption does not imply security.
            An attacker can examine all 26 possible shifts.
            Language statistics can help identify the most plausible one.
          

        

        

          
2. Statistical attack against Caesar

        
          

            We estimate English letter frequencies from a reference
            corpus. For each of the 26 candidate shifts, we decrypt
            the ciphertext and compute a chi-squared score.
            The lowest-scoring candidate is selected.
          

        
          

            Score = Σ (observed − expected)² / expected,
            where expected = message letter count × reference frequency.
            This is a ranking score, not a probability of correctness.

Observed results


          

            In one evaluation run, the attack recovered the correct key
            in 92 out of 100 trials for messages of 20 letters.
            For lengths of 50, 100, 200 and 500 letters, it recovered
            the correct key in all 100 trials at each length.
          

          
          

            These results suggest that longer messages provide more
            reliable letter-frequency information. Short messages can
            differ substantially from the reference distribution,
            sometimes causing an incorrect shift to receive a better score.
          

          
          

            The observed 100% success rate is not a guarantee for arbitrary
            messages. The experiment uses an opening excerpt of Jane Austen's
            Pride and Prejudice as its reference corpus and a separate
            AI-generated English passage as its evaluation text.
            Random extracts may overlap, and the results depend on the
            selected texts. New runs may produce different percentages.
          

        
          
Method and limitations

        
          
    
            
  • 
              Add-one smoothing gives every letter a nonzero reference
              probability: pᵢ = (countᵢ + 1) / (total letters + 26).
            
    • 
            
  • 
              Short messages may have frequencies unlike typical English.
              The best-scoring candidate is therefore not always correct.
            
    • 
            
  • 
              A corpus from another language, genre or domain may produce
              a less suitable model.
            
    • 
            
  • 
              The score uses individual-letter counts and ignores letter
              order. N-gram scoring could also use common letter sequences.
            
    • 
            
  • 
              All 26 shifts are examined. Exhaustive search generates the
              candidates; the statistical model ranks them automatically.
              Exact score ties are resolved by selecting the smallest shift.
            
    • 
            
  • 
              A low score is not a proof of correct decryption. We do not
              interpret it as a p-value, especially for short messages
              with small expected letter counts.

3. Hybrid encryption with secp256k1

        
          

            We use the same normalized message as the Caesar experiment.
            The recipient has a private scalar k and a public key Q = kG.
            For this experiment, k is deliberately restricted to 1,…,1000.
          

        
          
    
            
  1. 
              The sender generates a fresh ephemeral scalar r from the
              full valid secp256k1 scalar range and computes R = rG.
            
    2. 
            
  2. 
              The sender computes the shared point S = rQ.
              The recipient obtains the same point as S = kR.
            
    3. 
            
  3. 
              HKDF-SHA256 derives an AES-256 key from the shared
              point's x coordinate, a random salt and context information.
            
    4. 
            
  4. 
              AES-GCM encrypts the message using a fresh 12-byte IV
              and produces a 16-byte authentication tag.
            
    5. 
            
  5. 
              The recipient derives the same AES key and decrypts,
              verifying the authentication tag.

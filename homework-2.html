Homework 02

Encryption and Cryptanalysis

Comparing an elliptic-curve encryption scheme with the Caesar cipher, then investigating their weaknesses.

Aim of the experiments

We encrypt and decrypt the same message using two schemes: the Caesar cipher and a hybrid scheme based on secp256k1, with an intentionally restricted recipient private-key space.

We then investigate two attacks: statistical recovery of the Caesar shift and exhaustive search of the restricted elliptic-curve private-key space.

1. The Caesar cipher

Each letter is replaced by the letter a fixed number of positions further along the alphabet. We encode A,…,Z as 0,…,25.

Encryption: c = (p + s) mod 26.
Decryption: p = (c − s) mod 26.

Here p represents a plaintext letter, c a ciphertext letter, and s the secret shift. Encryption and decryption use the same key, so this is a symmetric cipher.

ASCII letters are converted to uppercase. Spaces, digits and ASCII punctuation are preserved. Accented letters are not supported in this experiment. Both encryption schemes will use the same normalized text.

Key space and statistical properties

        
          

            There are 26 possible shifts, including zero, which leaves
            the message unchanged. The same plaintext and key always
            produce the same ciphertext.
          

        
          

            Every occurrence of a letter is replaced by the same letter.
            Letter frequencies are therefore shifted, not hidden.
            Repeated-letter patterns remain visible. In this implementation,
            spaces and punctuation also reveal part of the message structure.
          

        
          

            Correct decryption does not imply security.
            An attacker can examine all 26 possible shifts.
            Language statistics can help identify the most plausible one.
          

        

        

          
2. Statistical attack against Caesar

        
          

            We estimate English letter frequencies from a reference
            corpus. For each of the 26 candidate shifts, we decrypt
            the ciphertext and compute a chi-squared score.
            The lowest-scoring candidate is selected.
          

        
          

            Score = Σ (observed − expected)² / expected,
            where expected = message letter count × reference frequency.
            This is a ranking score, not a probability of correctness.

Observed results


          

            In one evaluation run, the attack recovered the correct key
            in 92 out of 100 trials for messages of 20 letters.
            For lengths of 50, 100, 200 and 500 letters, it recovered
            the correct key in all 100 trials at each length.
          

          
          

            These results suggest that longer messages provide more
            reliable letter-frequency information. Short messages can
            differ substantially from the reference distribution,
            sometimes causing an incorrect shift to receive a better score.
          

          
          

            The observed 100% success rate is not a guarantee for arbitrary
            messages. The experiment uses an opening excerpt of Jane Austen's
            Pride and Prejudice as its reference corpus and a separate
            AI-generated English passage as its evaluation text.
            Random extracts may overlap, and the results depend on the
            selected texts. New runs may produce different percentages.
          

        
          
Method and limitations

        
          
    
            
  • 
              Add-one smoothing gives every letter a nonzero reference
              probability: pᵢ = (countᵢ + 1) / (total letters + 26).
            
    • 
            
  • 
              Short messages may have frequencies unlike typical English.
              The best-scoring candidate is therefore not always correct.
            
    • 
            
  • 
              A corpus from another language, genre or domain may produce
              a less suitable model.
            
    • 
            
  • 
              The score uses individual-letter counts and ignores letter
              order. N-gram scoring could also use common letter sequences.
            
    • 
            
  • 
              All 26 shifts are examined. Exhaustive search generates the
              candidates; the statistical model ranks them automatically.
              Exact score ties are resolved by selecting the smallest shift.
            
    • 
            
  • 
              A low score is not a proof of correct decryption. We do not
              interpret it as a p-value, especially for short messages
              with small expected letter counts.

3. Hybrid encryption with secp256k1

        
          

            We use the same normalized message as the Caesar experiment.
            The recipient has a private scalar k and a public key Q = kG.
            For this experiment, k is deliberately restricted to 1,…,1000.
          

        
          
    
            
  1. 
              The sender generates a fresh ephemeral scalar r from the
              full valid secp256k1 scalar range and computes R = rG.
            
    2. 
            
  2. 
              The sender computes the shared point S = rQ.
              The recipient obtains the same point as S = kR.
            
    3. 
            
  3. 
              HKDF-SHA256 derives an AES-256 key from the shared
              point's x coordinate, a random salt and context information.
            
    4. 
            
  4. 
              AES-GCM encrypts the message using a fresh 12-byte IV
              and produces a 16-byte authentication tag.
            
    5. 
            
  5.

4. Attack on the restricted ECC key space

        
          

            The attacker receives the recipient public key, the public
            encryption package and the known private-key bound.
            The original private key and plaintext are not inputs
            to the attack.
          

        
          

            For each candidate d from 1 to 1000, the attacker computes
            dG and compares it with the recipient public key Q.
            Once a match is found, the recovered private key is used
            to derive the AES key and decrypt the message.

5. Comparison and conclusions

        
          

            

              Caesar cipher and the educational ECC scheme
              
                

                  Aspect
                  Caesar cipher
                  ECC-based hybrid scheme
                

              
              
                

                  Keys
                  
                    The same secret shift is used for encryption and decryption.
                  
                  
                    The sender uses the recipient's public key.
                    The recipient uses the corresponding private key.
                    A fresh ephemeral key pair is generated for each encryption.
                  
                

        
                

                  Encryption
                  
                    Each letter is moved by a fixed number of positions
                    in the alphabet.
                  
                  
                    ECDH establishes a shared secret.
                    HKDF derives an AES key, and AES-GCM encrypts the message.
                  
                

        
                

                  Decryption
                  
                    Each letter is moved backwards by the same shift.
                  
                  
                    The recipient reconstructs the shared secret and AES key,
                    then decrypts the message and verifies the authentication tag.
                  
                

        
                

                  Key space in this experiment
                  
                    26 shifts, including shift 0, which leaves the text unchanged.
                  
                  
                    1,000 possible recipient private keys.
                    This deliberate restriction makes key recovery practical.
                  
                

        
                

                  Repeated encryption
                  
                    The same message and shift always produce the same ciphertext.
                  
                  
                    Fresh random values make repeated encryptions of the same
                    message produce different encrypted packages.
                  
                

        
                

                  Statistical properties
                  
                    Letter frequencies are preserved under a shifted alphabet.
                    Repeated letters and language patterns remain visible.
                    This implementation also preserves spaces and punctuation.
                  
                  
                    The encrypted bytes do not preserve the plaintext's letter
                    frequencies in the same way. However, message length
                    is still revealed.
                  
                

        
                

                  Attack implemented
                  
                    Rank all shifts by comparing the decrypted letter counts
                    with a reference language model.
                  
                  
                    Test candidate private keys until the calculated public key
                    matches the recipient's public key, then decrypt.
                  
                

        
                

                  How a candidate is identified
                  
                    A statistical score estimates which plaintext is most likely.
                    The best candidate can be wrong.
                  
                  
                    The public-key comparison gives an exact match within
                    the tested interval.
                  
                

        
                

                  Effect of message length
                  
                    Longer representative texts usually give more reliable
                    letter-frequency estimates.
                  
                  
                    Key recovery depends on the private-key search interval,
                    not on the language or length of the encrypted message.
                  
                

              
            

          

        
          
What the Caesar experiment shows

        
          

            In the recorded run, the statistical attack recovered the correct
            shift in 92 out of 100 trials for messages of 20 letters.
            It succeeded in all 100 trials at each tested length of
            50, 100, 200 and 500 letters.
            These results describe this experiment, rather than a guarantee
            for every English text.
          

        
          

            Short messages can have letter frequencies that differ greatly
            from the reference corpus. Names, unusual vocabulary and texts
            from another language can also reduce accuracy.
            Longer texts usually provide more stable frequency estimates.
            However, the sampled excerpts may overlap, so the trials should
            not be treated as fully independent observations.
          

        
          

            The attack combines exhaustive search and statistical analysis:
            it tests all 26 shifts and uses a chi-squared score to rank them.
            Exhaustive search alone lists the possibilities; the language
            model helps choose between them.
            An optional improvement would be to score common pairs or groups
            of letters, using bigrams or trigrams.
          

        
          
Why the restricted ECC key can be recovered

        
          

            The attacker knows the recipient's public key Q and the base point G.
            For each candidate d from 1 to 1,000, the attacker computes dG
            and compares it with Q.
            A match reveals the private key, which can then be used to
            reconstruct the shared secret and decrypt the message.
            No language model or known plaintext is required.
          

        
          

            This ascending search needs at most 1,000 candidate tests.
            If the private key were selected uniformly from this interval,
            the average would be 500.5 tests.
            In this implementation, a private key of 137 is found after
            exactly 137 candidate tests.
            Measured running times also depend on the device, browser
            and pauses used to keep the interface responsive.
          

        
          

            A set of 1,000 equally likely private keys provides only about
            log2(1,000) = 9.97 bits of uncertainty.
            Using AES-256 does not remove this weakness:
            recovering the recipient's private key allows the attacker
            to derive the AES key without attacking AES itself.
          

        
          
Why a full-size ECC key changes the problem

        
          

            A properly generated secp256k1 private key is selected from
            1 to n − 1, where n is the order of the base point and is
            approximately 2256.
            Searching this entire space by trying every private key
            is not practical.
          

        
          

            The best general classical discrete-logarithm attacks require
            roughly 2128 group operations, rather than
            2256. This is still beyond practical reach.
            Therefore, a 256-bit elliptic-curve key is commonly associated
            with approximately 128-bit classical security.
          

        
          

            If a key is known to lie in a small interval, methods such as
            baby-step giant-step or Pollard's kangaroo can reduce the
            search work to roughly the square root of the interval size,
            with different memory requirements.
            They are optional alternatives to the simple search implemented here.
          

        
          
Limitations of the educational scheme

        
          

            The deliberately small recipient private-key space is the
            weakness exploited by this attack. A fresh, full-size ephemeral
            key does not compensate for a weak recipient private key.
          

        
          

            The scheme also assumes that the sender has obtained the authentic
            recipient public key. AES-GCM detects changes to the encrypted
            message under the derived key, but it does not prove the sender's
            identity: anyone with the recipient's public key can create a
            new encrypted message.
          

        
          

            Random-looking ciphertext and successful statistical tests
            are not proofs of security. Security also depends on key generation,
            correct implementation and the surrounding protocol.
            This is an educational hybrid encryption demonstration,
            not the Ethereum transaction protocol.

Interpretation and limitations

  • Uniform sampling of the valid scalars gives uniform sampling of the non-identity points in the generated subgroup. It does not imply uniform coordinate frequencies.
  • Opposite points share the same x coordinate: (n − k)B = −kB. A point with y = 0 is its own opposite.
  • Coordinate bits need not be balanced. Their distribution depends on the curve, the subgroup and the chosen encoding.
  • Pearson correlation measures linear association only. A zero coefficient does not establish independence or security.
  • Hamming distances describe this finite experiment. They do not prove the strict avalanche criterion or establish that scalar multiplication behaves like a cryptographic hash.
  • The toy curve is easy to invert by enumeration. These results do not measure the security of secp256k1.

Discussion: scalar multiplication and cryptographic hashes

What the experiment shows

For G = (1, 5), the computation gives 6G = (5, 8). The base point has order 9: 9G = O, and the sequence repeats every 9 scalars. Therefore, the canonical nonzero private scalars are 1 to 8.

Each of these eight scalars produces a different public point. However, only four x coordinates occur, each twice. This follows from the symmetry between kG and (9 − k)G: opposite points share the same x coordinate.

With B = (6, 6), the order is 18 and the experiment covers all 17 finite points of the curve. The point (3, 0) is its own opposite, so its x coordinate occurs only once. All other observed x coordinates occur twice.

Why the toy example is not secure

Recovering k from Q = kG is the elliptic-curve discrete logarithm problem (ECDLP). In this example, it is easy: an attacker can enumerate the eight valid private scalars and compare their outputs with Q.

Real elliptic-curve cryptography uses carefully chosen, much larger groups. The toy curve illustrates the mathematical operations, but it does not reproduce their practical resistance to inversion.

Similarities and differences between the two transformations
Property Scalar multiplication k → kG Cryptographic hash
Determinism The same scalar and base produce the same point. The same input produces the same digest.
Efficient computation Efficient algorithms such as double-and-add exist. This application uses repeated addition to display every intermediate multiple. Efficiently computes a digest from an input message.
Resistance to inversion Depends on ECDLP hardness in the selected group. It is absent in this tiny example. Preimage resistance: finding an input for a given digest should be computationally infeasible.
Input and output A scalar modulo the base point order maps to a point in its subgroup. Variable-length messages map to fixed-length digests for a fixed-output hash.
Collisions Distinct canonical scalars produce distinct points. Repetition for k and k + n occurs when scalars outside the canonical range are allowed. Collisions must exist because the input space is larger than the output space, but finding them should be computationally infeasible.
Algebraic structure (a + b)G = aG + bG. This structure supports public-key protocols. A general-purpose cryptographic hash is not intended to preserve this additive relationship.
Bit changes Measured Hamming distances depend on the curve, scalar domain and point encoding. They do not establish ECDLP hardness. Strong diffusion is desirable: one input-bit change should affect each output bit with probability near one half under an appropriate input model. This alone does not establish security.

Statistical conclusions

Uniformly selecting a valid private scalar produces a uniform distribution over the corresponding non-identity public points. Projecting those points onto x or y can produce a nonuniform distribution. Point uniformity and coordinate uniformity are therefore different properties.

The binary representation also matters. Coordinates are encoded with five bits, but their values are restricted to 0 through 16. In the subgroup generated by G, every x coordinate is below 16, so its most significant bit is always zero. This imbalance is explained by the output domain.

The correlation coefficients and Hamming distances describe the enumerated data; they are not security tests. In particular, a near-zero Pearson coefficient does not exclude nonlinear or algebraic relationships. An average Hamming distance near half the output length does not establish the strict avalanche criterion.

Scalar multiplication is not a hash function. Its cryptographic value comes from an efficiently computable public-key relationship whose inversion is believed to be difficult in suitable groups. Random-looking output alone is neither a definition nor a proof of cryptographic security.
